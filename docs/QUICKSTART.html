Anveo Phone VoiceBot QuickStart

Fast Windows test guide for proving live bidirectional telephone audio. Phase 0 sends a test tone or WAV and captures caller PCM. Phase 1 adds an opt-in caller-turn response loop.

Before You Start

Use a test phone and tell the tester the call may be captured. Close normal AnveoPhone first. Disable AnveoPhone Auto-answer before running this test.

1. Confirm The Folder

  1. Extract or clone anveo-phone-voicebot.
  2. Keep the full folder together.
  3. Know the path to your AnveoPhone source folder, for example F:\anveophone.

2. Run The Logged Test Bundle

Open Command Prompt or PowerShell in the anveo-phone-voicebot folder and run:

run_phase0_tests.bat "F:\anveophone"

If you need to force the exact Python executable that runs AnveoPhone:

run_phase0_tests.bat "F:\anveophone" "C:\path\to\python.exe"

The script creates a ZIP under:

artifacts\test-runs\phase0-...\phase0-....zip

Send that ZIP back for troubleshooting.

3. Launch The Live Manual Call Test

From the same project folder, run:

launch_phase0.bat "F:\anveophone"

If needed, specify Python:

launch_phase0.bat "F:\anveophone" "C:\path\to\python.exe"

This opens the PCM server and launches AnveoPhone with the Phase 0 bridge armed for one incoming call.

You can also run the menu launcher with launch_app.bat; choose A for Phase 0 or H for the Phase 1 response test.

4. Optional Phase 1 Response Test

Phase 1 waits for caller audio, detects a pause, and returns generated audio through the same live PCM bridge. On Windows it uses built-in SAPI speech by default, with a fallback tone pattern if TTS fails.

launch_phase1.bat "F:\anveophone"

Before calling, confirm the Phase 1 server window prints phase1_response_prepared. source: sapi means spoken audio is ready; fallback_tone_after_tts_error means the call will use the tone pattern and the error is printed in that same line.

The same test also tries local Windows speech recognition. After the call, check the JSON report for phase1_transcript_source. sapi means caller words were recognized; none means the report kept the signal summary and may include recognition errors.

By default, the launcher uses --response-mode rules, so the spoken reply should follow simple greeting, scheduling, message, and hours rules. Use --response-mode echo when you want it to repeat the recognized words for diagnosis.

Optional spoken response with Piper:

set VOICEBOT_PIPER_MODEL=C:\path\to\voice.onnx
set VOICEBOT_PIPER_CONFIG=C:\path\to\voice.onnx.json
launch_phase1.bat "F:\anveophone"

Optional Windows voice selection:

set VOICEBOT_SAPI_VOICE=Microsoft Zira Desktop
launch_phase1.bat "F:\anveophone"

5. Make The Test Call

  1. Call your Anveo number from a test phone.
  2. Answer manually in AnveoPhone.
  3. Confirm the Events panel says Live PCM connected.
  4. For Phase 0, the caller should hear a one-second 440 Hz tone. For Phase 1, speak and pause, then listen for the response.
  5. Speak a clear phrase for at least five seconds.
  6. Hang up.

6. Check Output

File Location Meaning
Captured caller WAV artifacts\calls\*.wav Caller audio received by the bridge.
Call JSON report artifacts\calls\*.json Frame counts, signal stats, bidirectional PCM flag, and Phase 1 response details when used.
Test bundle ZIP artifacts\test-runs\phase0-...\*.zip Logs and diagnostics to send back.
