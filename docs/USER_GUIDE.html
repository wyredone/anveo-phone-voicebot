Anveo Phone VoiceBot User Guide

Setup, testing, logging, and troubleshooting guide for the standalone localhost PCM bridge between AnveoPhone and a separate receiver process.

Phase 0 Scope

Phase 0 proves telephone audio only. It captures incoming caller PCM and sends back a test tone or a supplied WAV. It does not answer calls automatically, run AI, transcribe speech, select personas, or perform production receptionist logic.

Phase 1 is available as an opt-in response loop. It detects caller speech, waits for a pause, and sends generated return audio. It can use built-in Windows SAPI speech or Piper for local TTS, but does not yet perform real STT or persona/brain logic.

Quick Test

  1. Close the normal AnveoPhone app.
  2. Disable AnveoPhone Auto-answer.
  3. Open Command Prompt or PowerShell in the anveo-phone-voicebot folder.
  4. Run the launcher with your real AnveoPhone path.
launch_phase0.bat "F:\anveophone"

If needed, specify the exact Python executable:

launch_phase0.bat "F:\anveophone" "C:\path\to\python.exe"

The launcher runs diagnostics, starts the PCM server in a second window, and opens AnveoPhone with the bridge armed for one incoming answered call.

The menu launcher launch_app.bat also exposes the Phase 1 response test as option H.

Live Call Test

  1. Run launch_phase0.bat.
  2. Wait for AnveoPhone to register normally.
  3. Call your Anveo number from a test phone.
  4. Answer manually in AnveoPhone.
  5. Confirm the Events panel shows Live PCM connected.
  6. Confirm the caller hears the one-second test tone or supplied WAV.
  7. Have the caller speak a clear phrase for at least five seconds.
  8. Hang up and inspect the capture/report files.

Hotkeys

KeyAction
F8Arm the next incoming answered call.
F9Release the bridge and restore manual audio.

Use A Custom WAV Response

Run the server separately if you want a spoken static response instead of the default tone. The WAV must be uncompressed 16,000 Hz mono 16-bit PCM and no longer than 30 seconds.

python -m voicebot serve --wav "F:\test_response.wav"

Then run the host in a second terminal with the same port/token defaults:

python -m voicebot host --anveophone "F:\anveophone" --arm-next-call

Phase 1 Response Test

Phase 1 uses the proven PCM bridge, waits for a caller turn, then sends generated response audio back into the call. Use it after Phase 0 shows bidirectional_pcm_observed: true.

launch_phase1.bat "F:\anveophone"

With the menu launcher, choose H. After answering the incoming call, speak briefly and pause for about one second. The caller should hear a response. On Windows, the default response uses SAPI speech. With Piper configured, Piper is used first. If local TTS fails, the response is a tone pattern.

The Phase 1 server prepares response audio before it starts listening. Confirm the server window prints phase1_response_prepared before placing the call. source: sapi means spoken audio is ready; fallback_tone_after_tts_error means it will play the tone pattern and includes the local TTS error.

The same run attempts local Windows speech recognition for the caller turn. The call report records phase1_transcript_source; sapi means recognized words were logged, and none means recognition returned nothing or failed. Any failure details are in phase1_transcript_errors.

The launcher uses --response-mode echo, so the reply acknowledges the recognized caller text. Use --response-mode fixed for the known static phrase while troubleshooting.

set VOICEBOT_PIPER_MODEL=C:\path\to\voice.onnx
set VOICEBOT_PIPER_CONFIG=C:\path\to\voice.onnx.json
launch_phase1.bat "F:\anveophone"

Optional Windows voice selection:

set VOICEBOT_SAPI_VOICE=Microsoft Zira Desktop
launch_phase1.bat "F:\anveophone"

Advanced server-only command:

python -m voicebot serve-ai --response-text "Hello. Phase one is connected."

The call report records mode: phase1, a placeholder transcript summary, response text, and response source.

Acceptance Checklist

Troubleshooting

SymptomLikely CauseFix
doctor cannot import PJSUA2 Wrong Python interpreter, missing DLL dependency, or mismatched _pjsua2.pyd. Run with the exact Python that your working AnveoPhone launcher uses.
Auto-answer error AnveoPhone Auto-answer is still enabled. Disable Auto-answer and rerun the launcher.
Port 8765 busy Old PCM server window is still open, or another app owns the port. Close old test windows, or use the same alternate --port for server and host.
No Live PCM connected event Call was not armed, not confirmed, outgoing, held, or media object was unavailable. Press F8 before the next incoming call, answer manually, then check logs.
Caller hears nothing Bridge did not attach, response queue did not drain, or native callback failed. Send the test-run ZIP and call JSON report.
No WAV capture Capture disabled or no caller audio arrived. Check the JSON report and rerun without --no-capture.

What Phase 0 Does Not Prove

  • It does not prove a human caller heard audio unless you verify it during a real test call.
  • It does not run Voice-Engine AI, STT, TTS, personas, or scheduling rules.
  • It does not answer calls automatically.
  • It does not make production decisions about which callers should be handled by the bot.
